## 1. Terminal Release Driver
Resolve ownership R1 P2 and capacity R1 P2 together. Parser REFUSED/CANCELLED remain terminal; begin/acceptDelivery/advance/finish/cancel never restart parsing there. Introduce a separate owner-only resource operation cleanupStep on an opaque resource-owner capability, not a parser operation or a new public MCP/API.
The resource owner and its serial driver are bound before begin and outlive the parser's terminal transition until release is confirmed or blocked. The same already-bound parent driver explicitly calls cleanupStep; no timer, worker, new job, replacement controller, hidden task or automatic recovery is created. Execution remains blocked until that driver's lifetime, serialization and finite dispatch envelope are proved.
cleanupStep is admitted only for that owner's REFUSED/CANCELLED resource set in pending state. Validate source/purpose/attempt/profile, owner generation and cleanup cursor. Only release cursor, exact work charges, resource records and live gauges can change; parser terminal state, bindings, input/grammar position and cumulative admissions stay fixed. No partial output, allocation of new payload, input admission, grammar, receiver transfer, retry or rebinding.
Use the original protected Wc=8388608 and per-call Ws=4096 candidates; both are inactive until separately qualified. Each valid call charges dispatch, checks, bookkeeping and bounded release work against remaining Wc, with total call work <=Ws. No reset, refund, borrowing, normal-work top-up or new cleanup allowance. Invalid calls preserve resource/parser invariants and charge the owner's separate finite dispatch ledger; exhaustion stops dispatch without inventing a parser transition.
Each pending continuation needs known finite progress and a resumable cursor. It may yield before an indivisible operation that does not fit the current step only if that operation fits a fresh Ws. A primitive larger than Ws rejects the profile; failure, unknown outcome, missing progress, owner loss or exhausted reserve blocks the resource set instead of retrying it. Preserve retained identities and unconfirmed ownership; block next acquisition.
Cfixed and release coefficients must include every cleanup-call/check overhead, the final confirmation and persistent parent control records. Wc/Ws=2048 is only a number of full-work quanta, not a proved maximum number of calls. Require a positive progress/work relation and a complete finite total bound; do not turn a small-work yield into unbounded scheduling.
Success needs confirmed logical release of all decoder-owned leases, private input, partial result and temporaries. Then cleanup becomes confirmed without changing REFUSED/CANCELLED. It is not GC, erasure or transport settlement.

## 2. Counter Units, Ledgers And Event Gates
Resolve counter R2 P2 with the proposed interpretation: scalar65536 applies separately to each decoded key/string token; numeric128 applies separately to each original ASCII numeric lexeme. Quote/escape syntax is excluded from decoded payload but still charges body/work. No new response-total scalar cap is invented; accumulated retained payload has its own capacity account. Boolean/null lengths are their fixed literals. Keep body524288, deliveries1024, nodes16384, depth32 and keys256/object unchanged.
Token-local gauges reset only at a new token; retained payload, reserved nodes/keys, received/admitted totals and work never receive a refund. Two 40 KiB strings are not rejected solely because their sum exceeds65536; they must still pass body, node, work and capacity gates. Confirm this interpretation against upstream M requirements before runtime adoption; unresolved disagreement blocks qualification, not silent substitution.
Choose exact nonnegative logical integers <=Imax=9007199254740991 as a pure-contract candidate, not a JS representation/primitive selection. Check addition, subtraction, multiplication, quotient/remainder and page rounding before use. For P>0, page(x)=x if divisible, otherwise x+(P-x%P), with checked intermediates. Unknown/noninteger/overflow terms refuse before retention/effect; never wrap, clamp or replace them with zero. Keep the previous exact observation separately from an unknown new observed total.
Receipt and admission are separate ledgers. The qualified parent receipt owner charges actual received bytes and callbacks once, including rejected ones. Admission consumes no second receipt charge. The bound receipt record identifies batch/response/sequence/extent and before/delta/after version; the parent guard checks that this receipt's after-total fits8388608, not that the post-receipt remainder can pay the same delta again. No unauthenticated caller numbers or races between receipt versions may substitute. All receipt/internal-source evidence gaps stay open.
Replace the global guard-before-grammar ordering. First perform bounded, inert operation/state/binding checks and charge dispatch. Invalid calls change no parser state. For a valid operation, before each check/effect reserve its checked finite work; a charged minimal grammar/context classification determines the applicable event. Syntax-invalid input reserves no fictitious node/key/depth slot. A quoted key start is eligible only in an object's key-expecting state, not after a key waiting for colon.
For each eligible event compute checked prospective counters and identify all required ownership/capacity/cleanup/work guards. Respect delivery/body/batch at admission, depth+node together for a legal container start, node for a legal scalar value start, key at eligible quoted key start, and scalar/numeric before append. Commit the tuple once only after all applicable guards pass. No scan-ahead ranking of future errors; deny without partial growth. Preserve positions and comparison/reservation phases across yields.
An unqualified/raw/misbound handle is a state-preserving contract error with charged owner dispatch. A qualified, correctly bound delivery whose storage/profile fails a suitability guard causes REFUSED before retention. Repeated invalid offers cannot obtain fresh dispatch budgets or trigger getters/host introspection.

## 3. Deterministic Lookup And Normal Work
Resolve capacity R2 lookup P2 without increasing Wn=16777216, Ws=4096, Wf=4096 or structural caps. Propose a per-object sorted reference index searched by bounded bytewise binary search, not a host sort/hash builtin. Preserve original property insertion order in separate edges; sorting the index must not reorder the result.
With k prior unique keys, use at most ceil(log2(k+1)) key comparisons, k<=255 for an admitted next key; empty index costs no byte comparison but still charged control work. Every comparison charges both byte reads, comparison and control/length checks, with resumable offsets. Duplicate recognition remains before colon/value parsing, including equal-value and escaped aliases.
At most8 comparisons per admitted key imply a byte-pair examination bound8*Ukeys, conditional on the source-to-decoded-key proof. This is not8*Ukeys total work: read, compare, control and decoding weights are additional. The review's 256-key/2042-byte case no longer uses linear lookup's 66650880 byte pairs, but no claim is made that its complete charged work necessarily fits Wn.
Insertion may shift at most k references. Charge every reference field read/write, reservation and metadata operation; allow bounded resumable shifts with no duplicate commit. A conservative shift bound is sum_o(Ko*(Ko-1)/2) <=255*J/2 when total indexed key slots<=J and Ko<=256. Reference width, temporary slot and per-operation coefficients remain UNSET until the complete layout is proved. No implicit constant-time compare/memmove.
Release temporary lookup-index ownership incrementally at object close under READY/YIELDED normal work, without releasing key text/edges retained by the result. Do not leave an unbounded lookup-record sweep for finish. Exact phase/cursor and bounded release facts are qualification gates. Objects remain uncompleted while their required index release is pending.
Before finish, all input/carry/lookup/parser temporaries must be logically released or fit the qualified one-step finish reserve. Root result storage alone crosses the handoff; no deferred finish or bigger step. Structural validity does not guarantee acceptance within the work limit; exhaustion still refuses before publication.

## 4. Capacity By Allocation Identity
Resolve capacity R2 paging P2 and associated R1 notes. For each distinct simultaneously retained allocation i, use a manifest entry for identity/generation, owner, aliases, requested payload, rounded capacity, header/alignment and lifetime. Add view/lease/control metadata separately; equal-content copies are distinct, shared backing counted once in full.
Replace unconditional page(sum payload) by sum_i page(payloadCapacity_i) plus each allocation's evidenced header/alignment/metadata. Grouping into page(U) or page(N*mNode) is allowed only for a single qualified pool, or an explicitly bounded pooled layout whose every allocation is included. Per-string/per-object allocation cannot borrow another allocation's unused page tail.
For A positive integer-payload allocations with P=1024, sum_i page(ui) <= sum_i ui +1023*A. Zero-length resources still need their own nonzero metadata and any profile minimum allocation charge. Record A and the allocator/layout bounds before applying this inequality; no guessed allocator behavior. Do not use logical U<=B as a whole-heap/RSS bound.
For an optional one-payload-per-key/value layout, N+J=32800 is only a conservative slot-count candidate pending the J=N+D correspondence proof; it is not an adopted allocation count. Pool/control/index/carry/temporary allocations are additional. Until a full allocation manifest fixes all counts and sizes, root peak is UNKNOWN and execution blocked.
Define Rbase as bounded acquisition-wide fixed/control/receipt/hash/outcome records; Oretained as earlier results/rows/projection still owned anywhere in the same acquisition root. Both need manifests, disjointness from phase resources and finite bounds. They are not zero defaults. Current result remains in root accounting after receiver handoff.
Source-side manifests must bound simultaneous producer-held backing count Qsrc and each full backing capacity Ssrc, including pools, prebuffering and retention after decoder lease release. Qsrc*Ssrc is usable only if uniform bounds are proved; delivery1024 and one active parser input do not prove these bounds for hidden producer allocations.
Projection is a separate domain: the review cites the M projection cap1048576 (2B), requiring exact existing-contract linkage and representation correspondence before use. A serialized-byte cap does not alone bound UTF-16 backing, headers or coexisting copies. Either explicitly account for all such storage or exclude the representation and block its use; never silently count it as zero.
Keep COPY_PENDING/RELEASE_SOURCE/PARSE_READY/RELEASE_INPUT/finish live-set overlap, carry and error storage in the maximum; use max only when non-overlap is proved. Budget ownership transfer does not release root-retained resources.

## 5. Related Ownership Clarifications
Bind receiver identity/generation and source/purpose/attempt/profile at begin together with the resource owner; finish must validate the same qualified receiver's readiness. No retargeting, callback or second handoff. Missing binding/capability proof blocks execution.
Serial cancellation is admitted only between serial operations while nonterminal, including before finish starts. Do not promise cancellation during a synchronous non-reentrant finish. Its handoff remains one qualified atomic/non-failing commit; DONE cannot be reversed and an unknown return cannot republish.
All decoder temporaries and obligations must be resolved before that commit. Remove the suggestion of pending decoder cleanup after DONE. A later parent accounting fault is reported on the acquisition root without reversing DONE or releasing receiver-owned result storage.
Before releasing private input at a delivery boundary, promote every needed token fragment into independently owned bounded carry/payload storage. No retained source/private-input view or substring is a copy proof. Incomplete UTF-8 needs at most3 raw continuation-prefix bytes; numeric raw carry is within128, key/string text within the per-token65536 plus charged codec fields. Exact codec-field layout and copies stay UNSET, never free. Progress cannot depend on already released input.
