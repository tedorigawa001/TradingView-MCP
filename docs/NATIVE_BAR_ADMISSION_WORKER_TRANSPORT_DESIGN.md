## Narrow READY Contract Proposal

At the design baseline, READY was `{ addon_protocol: 6, mode: "synthetic_only", pins_sha256 }` and could not declare a worker domain. The **sole wire-shape addition** is required `READY.payload.worker_clock_domain`, using the existing bounded `label` schema. It was subsequently approved and implemented only in the pure still-sealed v2 path in B4-A, as recorded below; it does not modify native protocol 6, v1 transport, price/scenario evaluation or notification conditions.

- The worker creates its own private domain at invocation start and declares it once in the original READY. It is a separate domain, never the parent's label or a caller clock.
- Parent accepts that domain only with the original worker/session, correct binding/ordinal, prior started LAUNCH write, synthetic-only/protocol-6 result and exact `pins_sha256 === digest(launchBinding)`. A declared domain is not OS clock authentication.
- BASELINED must declare that same domain; every trace event uses it with nondecreasing worker-local points. A missing/changed domain permanently stops the case. Do not infer the domain from the first trace or retrofit a prior READY.
- Keep `pins_sha256` as the binding digest. The complete READY frame digest, already committed as `ready_sha256` in the first create intent, also covers the new field. No extra frame, receipt kind, journal, binding mutation or timestamp field is needed.
- Recalculate maximal READY/frame/stop/report/coordinator serialization in the existing capacity contracts. No dual-shape decoder or silent downgrade; old and new peers are not mixed. Previously saved bytes are not reinterpreted as a current session.

All other messages keep their current schemas and directions. If implementation finds another wire-shape need, stop and propose it separately rather than expanding LAUNCH/PREPARE/FAILED here.

## Retained Lifetime Reference Proposal

A referenced deadline timer is not a permanent lifetime anchor: after it fires, a pending Promise or retained JS object alone does not establish that the worker stays alive. Do not assume that an idle writable status pipe provides that guarantee, or renew settlement timers to keep the process alive.

Propose **one private `MessageChannel` pair per worker invocation**, from a separately allowlisted `node:worker_threads` import, created before any original query can exist. This creates no Worker/thread and is never an application transport: neither port is exported, transferred, serialized or used for `postMessage`. A new Node port starts unreferenced, so the fixed implementation attaches its fixed `message`/`messageerror`/`close` listeners once, then calls `ref()` explicitly and qualifies `hasRef()`; unexpected messages invalidate the session. Node also unreferences a port silently when its last `message` listener is removed, even after an explicit `ref()`. Those listeners are therefore never removed, `once("message")` is not used, and `hasRef()` is rechecked before each new tracked action; a lost reference stops new work without a replacement anchor. The explicit allocation and its one close call belong to worker harness accounting, not native managed-FD counters. Missing creation/reference qualification blocks before native work, with no fallback anchor.

The ports remain referenced while original query/release/close or status-write disposition is pending/unknown, including after EOF, a clock fault or the original grace expiring. They authorize **no** new query, timed action, grace or cleanup. Only confirmed terminal tracked-work disposition allows one `close()` call on an original port. The ports are entangled: that call closes both, returns nothing, and is confirmed only by the asynchronous `close` event on each original port. A later `close()` on either port is a no-op, not a second attempt. A throw or a missing event leaves the close unknown with its original references and diagnostic, never a replacement channel or retry. A stuck worker remains for user action under the existing no-signal policy. Source tests must pin this one callsite and forbid Worker construction, posting/transferring ports, unref, `message` listener removal or `once`, and caller-selected keepalive mechanisms. Memory tests use invented ports and deny real `MessageChannel` as well as Worker creation. Invented ports must model Node's default-unreferenced state, listener-driven ref/unref and entangled close, so a silent unref or a second close is testable.

This is an additional design approval point, not an implemented connection or approval to allocate ports now. B4-A may model its lifetime and exact resource reservation only. B4-C/B4-D need separate approval for the unexecuted connection and its original-close integration. Operational allocation still requires the later opened worker entry and complete host/operational approval.

## Launch And Startup

### Parent Side

1. Require the original qualified build/namespace, exact next catalog allocation, adequate original 900000-ms case remainder, original case receipt/readback and a free cohort worker slot. Case preparation already started at allocation; launch does not restart it.
2. Reserve the original session and launch attempt before asynchronous qualifications/imports. After each await, recheck original cohort/case/slot ownership, stop state, current pins, phase remainder and output reservations. A competing continuation cannot acquire another slot.
3. Resolve only the fixed reviewed Node binary and new worker source from that invocation's pinned closure. Mode selects only the fixed normal/UBSan tree from the original allocation; no discovery/fallback or caller path. Stage new worker/helper source before a future fresh build so the complete manifest covers it; the old 436 outputs cannot supply it.
4. Install referenced preparation/transport supervision before launching. Fixed `spawn`, no shell, no exec/fork/synchronous fallback, `detached: true`, referenced child, fixed allowlisted environment and `stdio: ["ignore", "pipe", "pipe", "pipe", "pipe"]`. FD 3 is parent-to-worker commands; FD 4 is worker-to-parent status. libuv creates these stdio pipes as socket pairs, so each is bidirectional at the OS level: the parent also consumes FD 3's readable side, only to detect unexpected reverse bytes, and never writes FD 4; the worker never writes FD 3. No IPC channel or signal-based control is added.
5. Set only the original mode selector and the reviewed private build/scratch environment, including the existing UBSan options `halt_on_error=1:abort_on_error=0:exitcode=86:print_stacktrace=0`. Reject unsupported startup options/injection as required by host qualification. Environment does not open the worker entry or prove approval.
6. Retain the original child immediately and attach error/close/pipe/stdout/stderr handlers before any await or LAUNCH write. Partial spawn/stdio failure consumes the attempt and retains all returned original references. No retry or replacement child. A worker slot is not released just because `exit` happened; pipe/close/finalization outcomes remain separate.

### Worker Side

The future private worker root must establish its own original clock/latches and referenced command supervision before effectful startup. Its command parser reads the complete LAUNCH before interpreting any setup packet. It then eagerly loads every exact module it could need later, including the fixed compiled registry/reader/contracts and both fixed owner profiles, before READY. Eager loading does not enroll an owner or create a private key.

The worker loads only its fixed mode's addon and verifies synthetic-only/protocol 6, exact startup/module/artifact pins and the new source-bound facade before READY. Build/set digests are not a substitute for the exact module manifest. Where the existing small LAUNCH contains only digests, the worker may read the bounded fixed original build record in this same approved invocation, verify its bytes against `build_record_sha256`, parse its bounded role-tagged lists and recompute the exact sets. It does not adopt that file as a live grant or receive a new arbitrary path/full manifest over the pipe. Use the B3 row/byte/work ceilings and streaming checks, not a relaxed generic DTO parser. Missing closure, unsupported resolution, insufficient reserved hash/helper work or absent host/signature qualification blocks startup.

LAUNCH is not approval. The future separately reviewed worker unseal and original inherited channels are also required; this design adds neither. Pin checks of a worker's own source/body remain consistency checks under the stated launch assumption. Module import/cache handling and the exact native-load callsite require a dedicated boundary review; no dynamic import may first read a helper at GO or later. Any required initialization hidden in an imported module must be identified in its closure and cost plan before an operational entry opens.

READY occurs before any fixture exists. PREPARE uses the unchanged strict configuration validator, the one sealed setup/registration/envelope and the original launch nonce. U4 changes only the prescribed supplied data inode and consequent registration hash; the supervisor retains the correct ownership/setup facts. Bootstrap preparation, public verification material and actual baseline counters are separate from owner/query enrollment. BASELINED is derived from the original bootstrap/addon and repeats the READY domain, never zero/expected counters.

## Parent Writes And Receive Order

The runtime has one pending command write at most. A pending-operation ledger belongs to the original case session and is shared by ordinary sends and shutdown; there is no parallel CANCEL queue or second ordinal allocator.

| Fact | Meaning and irreversible accounting |
|---|---|
| Frame planned | Full canonical JSON plus LF, exact original binding and next directional ordinal checked against current v2 state/caps. Planning alone does not start query time |
| Write started | Immediately before invoking the original stream's `write`, consume the operation identity and record the original started fact. For GO this is submitted and starts the original parent query window |
| Callback completed | Kernel buffer accepted the bytes; not proof the worker read them or started a query |
| Throw/error/timeout | Started write becomes uncertain; no resend, new pipe or guessed acknowledgement. Retain actual later callback/close outcome once |
| Child frame before write callback | May be valid after write-start if the existing protocol permits it. Never fabricate write completion from READY/BASELINED/RELEASED |

Before planning and again at actual write-start, after all asynchronous qualifications, require original session/stream/child liveness, applicable original B2 phase, unchanged generation, sufficient frame/byte reservation, and current source/evidence proofs. GO additionally requires actual baseline/go-intent readbacks and independent pre-GO bound-object proofs supplied by the later B5 driver. Until that original producer exists, GO remains blocked; a model receipt is not the alternative.

Serialize before side effects, measure the complete frame including LF, and retain at most its one fixed copy. `write() === false` is backpressure, not an additional send or proof of failure. Supervise the same write callback to its original deadline, without looping on `drain` to resend bytes. Synchronous throws may still mean uncertain delivery once write-start was recorded. No caller can insert a prebuilt line, fake callback or alternate stream.

Receive fatal UTF-8/canonical LF frames through bounded incremental decoding. Process each complete frame in stream order through the existing protocol/coordinator; no concurrent per-frame awaits, unbounded raw queue or parser reset after stop. Both directions, terminal frames and permitted late-frame summaries share the existing 32-frame ceiling. EOF with a partial frame, wrong direction/ordinal/binding, repeated READY/OBSERVED/RELEASED or a frame after normal terminal state stops; it is not resynchronized into a new session.

Strictly valid post-stop arrivals enter only the existing bounded late-fact path, not ordinary progress. At most four late frame summaries retain count/hash/size without promoting release or creating evidence. Malformed/oversized or excess post-stop data stops further parsing/capture; preserve the bounded original resource/disposition record, not raw payloads. Stdout/stderr are not protocol channels: any unexpected output stops, even within the existing 8192-byte prefix-per-stream summary. Reverse-direction bytes on FD 3 also stop immediately; only their bounded byte count is kept, with no additional prefix capture or frame parsing. Do not report a prefix hash as a complete-stream hash after overflow.

If the parent clock can no longer issue a point, record already-known original close/exit/write outcomes in the private bounded terminal ledger with unavailable timestamp, not by feeding the last valid point as a new B2 event. The coordinator remains stopped/unadvanced; its timed API does not acquire an unqualified clock-recovery path. Such terminal facts cannot establish a timed CANCEL or final PASS. This is descriptive resource disposition, not a new receipt stream.

## GO And Original Query Lifetime

The worker consumes GO exactly once **before** its checks or awaits, then rechecks its validated session and sealed configuration. It never accepts a second GO, a new owner, alternate recipe or replacement query after refusal. Cancellation/EOF seen before original query creation is remembered; after each await and immediately before a new original action, the worker checks that latch.

- U0 selects only its catalog-declared unavailable/unsigned owner path and creates no private test key.
- Fixed-owner cases call only the reviewed `enrollFixedMemoryCheckpointOracleC0Only` with the original grant, sequence `1` and exact sealed enrollment tip. No legacy unrestricted export, `advance`, `setMode`, held/replayed packet or supplied signer/backend. Existing C0 and repeated/non-C0 rejection still precede signing.
- Once original owner/reader/query exist, keep their references separately with acquisition/close-attempt/disposition flags. Parent stop cannot retract a GO already written; it cannot guarantee that no C0 was signed. No signature/checkpoint/key bytes leave that worker-owned path or are saved.
- The test facade preserves each original function, receiver, argument, result and exception. It emits bounded begin/end/throw observations only; instrumentation failure latches acceptance failure but never substitutes an API result or calls the native API again.
- OBSERVED is a projection of original diagnostic/inventory/capture data plus explicitly labeled source-pinned re-derivation. No expected catalog value fills a missing observation. Its unavailable/overflow flags remain explicit; direct C0/retirement timestamps remain null. U3 private mapping and U4 bare-location limitations stay BLOCKED unless the existing named inference/proof conditions suffice.
- RELEASED requires the original query retirement/release diagnostic, confirmed cleanup and actual baseline/end resource match with no required close error. An incomplete optional projection cannot suppress a genuine release; send availability facts rather than forging full observations. Worker release alone never authorizes parent fixture removal.
- A begin refusal after GO with no query has no RELEASED. FAILED records actual `query_created: false` and available/null resource facts; parent retains the fixture and stops. Exit or zero-looking counters cannot repair it.

Normal result emission remains bounded trace chunks, at most one OBSERVED, then RELEASED with their exact accepted counts/hashes. FAILED is terminal and replaces normal progress, not a new attempt. After genuine release the worker remains available only for the original FINALIZE, which the parent may send after B5 confirms teardown. Parent cannot invent that confirmation in B4 memory tests as imported-runtime authority.

## Stop Cancel EOF And Close

Never make the ordinary stopped checkpoint permissive. A distinct narrow shutdown dispatcher can only consume the existing original CANCEL reservation, on the original live qualified command pipe, within the original settlement window, with known binding/ordinal/delivery state and available shared frame budget.

- Recheck at actual shutdown write-start. An already planned but unstarted ordinary CANCEL can be used once at its original ordinal; no second CANCEL is allocated.
- Any uncertain prior command write, including GO, makes the pipe delivery/ordinal state insufficient for shutdown CANCEL under the existing model: **close only**. Possibly started GO is not permission to guess a stream boundary. Do not concatenate CANCEL after a possibly partial frame.
- No submitted GO, worker already exited, accepted terminal result, closed/unqualified pipe, consumed cancellation, clock fault, missing phase proof or elapsed settlement window also means close only.
- Every stop consumes one original command-pipe close attempt, including pre-GO stops and unsuccessful/withheld CANCEL. A close attempt is separate from confirmed `finish`/`close`/error results. Never reopen, call generic `destroy` as a replacement, signal, retry an uncertain close, or mark completion from a timeout. Non-fixture original descriptor disposition stays possible even if the clock/namespace is invalid.
- Late callbacks/close/exit facts may settle their own original operations once. They cannot reset latches, begin a new settlement grace, free an unknown case slot, issue GO/FINALIZE, write new success evidence or permit cleanup.

The worker's original command EOF/error/parent loss sets failure once. Before GO it closes any original bootstrap without owner/query creation. After GO it cancels only its original query once when it exists, then attempts each original release/reader/owner/bootstrap disposition independently, retaining the first primary error plus bounded secondary close errors. Do not retry an uncertain native close. Pending query/close state must remain referenced; a reader's unref'd internal deadline is not sufficient to keep it alive.

Validated LAUNCH permits at most the one bounded attributed FAILED packet, and only while its original status write can still be qualified and timed. Clock failure or exhausted original time can withhold that packet; do not fabricate a stamp, renew the grace or promise it was flushed. Without validated LAUNCH, malformed startup ends through original channel closure/abnormal disposition, not an invented case-attributed packet. A FAILED worker exits nonzero naturally only when tracked original work is no longer pending and its allowed status write/close has settled. Its nonzero status comes from one fixed `process.exitCode` assignment when the failure latch is set, never cleared or lowered and distinct from sanitizer code 86; source tests pin that single callsite. No `process.exit`, forced GC, timer unref or child disappearance is release proof. A hung original operation stays retained through the separately proposed lifetime reference; default termination remains none, with user action required, not an automatic signal policy.

## Clocks Reservations And Capacity

Parent clock/origin/end come exclusively from reviewed B3-C. Never reset at worker readiness, mode change, command send or case retirement. The worker uses its own original monotonic origin/domain and same-sample UTC/JST stamping; points are compared only within their own domain. Parent receive times are distinct from worker trace times and cannot establish an exact cross-process dispatch/retirement interval.

Parent worker/command supervision needs a **new private phase-bound timer connection**, not an additional `kind` that turns the current qualification timer into a generic supplied-deadline service. It takes only internally owned B2 phase/session references. A command's fixed reservation uses its original planning point plus the existing capped full-ms remainder, bounded by original phase/invocation ends; actual write-start rechecks that same deadline and never resets it. The [exact rounding formula](NATIVE_BAR_ADMISSION_PARENT_CONNECTION_DESIGN.md#command-planning-and-write-start) preserves the reviewed model/P1/P3 rule; older write-start-plus-cap prose was not the implemented contract. Timers are referenced, generation/segment-bound, cancelled/settled once, preserve failed re-arm state and unknown references as in the reviewed B3-C correction. They also inherit the `c1207aa` second-review corrections. An arm or reference failure records the stop before its cancel, so the primary cause survives. The expiry callback receives the actual reason: only a genuine phase/invocation deadline is reported as a deadline, while rollback, clock fault, lost reference or unknown clear keeps a distinct timer-stop code. A close or write callback arriving after the deadline is late regardless of callback order. Timer/clock faults stop new writes; later valid points do not recover.

The current B3 metadata transport uses an entry-bound qualification timer. After case allocation, case-related pin/ACL helpers must use the new privately owned phase-bound helper lane as well, keeping the `c1207aa` clock check after every synchronous OS return before the next action; calling that old transport unchanged would not enforce min(10000 ms, remaining case phase). Builder-only metadata/discovery/compiler behavior stays unchanged. The B4-B review must cover the exact internal routing, pre/post-await phase checks and shared one-helper slot, not widen a public callback or arbitrary deadline option. B5 observer/writer consumers will need the same original-phase restriction later.

Worker-local preparation starts at its original invocation/startup, not each command. Its local query supervision begins at original GO receipt/start, while parent query time began at parent write-start; neither translates the other's clock. The original native reader deadline is not changed. Settlement starts once from that domain's first original trigger, and late frames/repeated CANCEL do not renew it. Referenced pending-operation supervision preserves lifetime after EOF; no interval, signal, restart or new grace handles a synchronous call that failed to return. These are limits/detection, not an interrupt guarantee.

Retain the existing ceilings, recomputing exact serialized costs before effects:

| Item | Existing bound / required check |
|---|---|
| Complete frame | 65536 UTF-8 bytes including LF; configuration 60000; 32 frames across both directions |
| Functional sequence | At most 17 frames (nine nontrace, eight trace); READY domain adds bytes, not a frame |
| Trace | 128 events, 1024 bytes/event, 16/chunk, eight chunks; no sampled replacement or truncation described as complete |
| Projection/failure | OBSERVED 16384 bytes; close errors at most eight; strict existing FAILED shape |
| Wire buffering | At most one 65536-byte parent command; decoder pending frame at most 65536 and existing input-batch cap `32 * 65536`; no unbounded parsed-frame backlog |
| Output/late facts | Existing 8192-byte prefix each stdout/stderr; at most four late frame hash/size summaries; retain overflow/unknown completeness |
| Retention anchor | Proposed one worker-private MessageChannel pair, two original ports; no message queue, Worker/thread, exported port or renewal. One close-call slot and two `close`-event outcome slots must be reserved separately |
| Parent model diagnostics | Existing 16384-byte diagnostic and 65536-byte canonical coordinator metadata; wire/trace/transient buffers separately charged, not claimed to fit that metadata bound or to prove V8 heap peaks |
| Evidence | 64 receipt records / 1 MiB, 16384/record, 262144/report, 131072/index; current stop summary at most six details within existing reserved events; no new log/receipt kind |
| Time | 120000 preparation, 600000 query, 60000 settlement, 120000 teardown, min(10000, remaining phase) command/helper/observer; original 900000-ms case fit |

B4-A must quantify its worst retained/transient wire state, flags/counters, exact maximal READY/FAILED and stop diagnostic sizes without raising these ceilings. B4 startup must reserve actual per-worker pin/hash/metadata work and helper counts against B3's unchanged limits, including repeated mode/case starts. No extra full-manifest hash at every message, uncharged second pass or guessed budget. A missing verified work plan, future total duration or source/patch producer keeps the runtime blocked. Observer work/native counters stay distinct from parent/worker pipe and JS buffer accounting.

## B4-A Lifetime Model Correction

| Supplied model event | State and refusal |
|---|---|
| `allocate({ports})` | One local invented pair identity. Both original ports must start `unreferenced`; absence/unknown or an already-referenced allocation stops qualification. A session stopped before allocation cannot allocate. No replacement pair |
| `noteListeners(pair,{index,event})` | `installed` represents attaching the fixed message/messageerror/close listener group once and the message listener's automatic reference. It is not sufficient qualification. `removed` represents loss of the fixed message listener and silently unreferences that port, invalidates its qualification and stops. Reinstall is refused. Unexpected `message`/`messageerror` stops. After the close call, these events from an end not yet closed still stop with their own reason and leave close progress unchanged; no listener can be installed |
| `referencePort(pair,{index,outcome,has_ref})` | One explicit-ref result per original port, after listener installation. Only `returned` plus `has_ref:true` qualifies; throw, unknown, false or unavailable observation stops. No retry to regain qualification |
| `beginWork(pair,{kind,ordinal,references})` | Every original work enrollment requires new supplied reference observations for both ports, as well as the original listener/ref qualification. Unreferenced/unknown/absent stops before enrollment; omitted observations refuse. A later positive observation cannot recover a stopped session |
| `settleWork(work,{outcome})` | Existing pending work may settle once after any stop, without a clock or new grace. Unknown work remains unknown and prevents close. The original 32 status writes plus five roles remain the maximum 37 records |
| `closePort(pair,{index,outcome})` | Only after every original work outcome is confirmed. | `observeClose(pair,{index})` | Separate once-only original asynchronous notification for each identified original end, even if a later reference observation said `absent`. One notification never confirms the peer. Both notifications confirm the recorded close disposition, even after a throw/unknown result, without changing that result or the first stop. A spontaneous notification records only that end and stops; it does not claim a close call, close the peer or grant work/cleanup authority. An absent/unknown allocation identifies no original end to close or confirm |
