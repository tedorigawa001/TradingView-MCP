# Synthetic Native Filesystem Foundation

Phase 1 and the read-only slice B of the approved 105-3 maintenance design, 2026-10-23 JST. This is **not a production deletion backend**. There is no MCP registration, server import, production-root support, writer-lock integration, classifier integration, journal publication, recovery grant or retention decision here. The existing production-maintenance refusal stays in force.

## Explicit Local Verification

On macOS with local Node headers and the Apple C++ toolchain:

```sh
bdo npm run test:native-bar-fs:synthetic
bdo npm run test:native-bar-fs:synthetic -- --ubsan
```

The runner compiles TypeScript, explicitly builds the addon and runs `test/native/nativeBarFs.test.mjs` plus `test/native/nativeBarRead.test.mjs`. UBSan stops on its first error; the runner rebuilds the normal synthetic binary afterward, including on a failed test. No network downloads, runtime compilation, startup hooks or automatic cleanup are added to the server. Ordinary `build`, `prepack` and `npm test` do not build this addon. The `.node` output under ignored `build/native-bar-fs/` is not in the package's publish allowlist. The read extension uses the local macOS CoreFoundation framework for UTF-8 validation and conservative normalized/case-folded name comparisons.

Only the locally tested macOS arm64/local APFS combination is qualified for these synthetic tests. Other architectures, volumes, ignored-ownership mounts and missing APIs are not production-qualified. Unsupported backends fail closed; the optional loader returns unavailable without a pathname-based mutation fallback.

## Primitive Contract

- The C++ build requires `NATIVE_BAR_SYNTHETIC_ONLY`. Its native root gate accepts only `<resolved $TMPDIR, or /tmp when unset>/native-bar-fs-synthetic-<six alphanumeric characters>/store`, with an owner-private sibling marker containing exactly `synthetic-fixture-v1\n`. It walks components using no-follow directory descriptors, not `realpath` followed by pathname mutation. `realpath` is used only to select the temporary anchor.
- `openSyntheticNativeBarFs` retains opaque process-local root/ancestor references. Read-only open and inspect create no entries. Both steady-clock and wall-clock deadlines are issued once, at most ten minutes. Expiry detected by an operation, explicit close and finalization release descriptors only. There is no expiry timer or deleting finalizer. Returned target closures may retain their issuing JS session until all handles are released.
- `inspect(area, day, name)` accepts only `captures`/`receipts`, a structural `YYYY-MM-DD` component and a lowercase UUID `.json` basename. This is path grammar, not calendar, capture, receipt or cleanup eligibility validation. No arbitrary path, destination, staging glob or supplied inode is accepted. It pins the original file descriptor, rejects nonregular objects, unsafe mode/owner/ACL, unknown hard links and files above 1 MiB, then hashes bounded raw bytes and compares before/after metadata.
- Proof includes lossless decimal device/inode/size/owner/mode/link/time values and SHA-256. A different inode with identical bytes is not the same target. ACLs are read from opened objects, absent/deny-only accepted, grants/errors refused. Darwin's absent-ACL `ENOENT` is separately confirmed by successful `fstatx_np` and `filesec_query_property` on the same descriptor, not treated as blanket permission to ignore ACL failures. See [Apple's ACL retrieval implementation](https://github.com/apple-oss-distributions/Libc/blob/main/posix1e/acl_file.c).
- `stage()` allocates an exclusive private operation slot and performs `renameatx_np` with `RENAME_EXCL`, `RENAME_NOFOLLOW_ANY` and `RENAME_RESOLVE_BENEATH`. It verifies the moved entry against the pinned original, permitting only the ctime change caused by rename, and syncs the file/affected directories. There is no replacement rename or copy/delete fallback. Every generated slot remains within pinned root descriptors.
- `purge()` accepts only that session's successfully staged and freshly reverified holding object. It uses `unlinkat` on the pinned slot, syncs the slot, checks absence and checks that the original opened inode has no remaining links. The primitive does not establish age, human consent or permission to delete real data.
- `status()` is a cached in-memory outcome, not a new filesystem verification or restart journal. `moved` distinguishes pre-move refusal from a move already performed. `conflict` preserves unexpected entries; `durability_unknown` never claims a certain completed transaction. No automatic retry, restore, directory removal or adoption of existing holding bytes is implemented. Empty slots and conflicts remain for later explicitly approved recovery design.
- Limits: eight live root sessions, 32 live targets per session and 512 native descriptors process-wide. Operations are bounded and synchronous in the MCP process; no independent child worker can outlive its writer. This primitive is not yet wired to a writer lock.

The synthetic-only callbacks force substitutions/interruption at named boundaries. They must return synchronously with no value, cannot reenter/close an active session, and are not MCP parameters or production APIs.

## Evidence And Remaining Gates

The dedicated tests use fresh synthetic roots and sibling victim fixtures only. They cover native successful move/unlink, namespace substitution, identical-byte inode replacement, changed bytes, explicit/inherited ACL grants, hard links/FIFO/oversize, exclusive destination collision, expiry, interrupted outcomes, bounded handles, optional-backend absence, actual process kill and GC without deletion. The UBSan run exercises the same suite. These are actual filesystem operations, not TypeScript filesystem mocks.

Pre-commit review on 2026-10-23 JST corrected a test-only gap: numeric negative arguments to Node's `utimesSync` become the current time. The fixture now supplies a negative `Date` and first verifies an actual `-500000000ns` mtime. Four added tests cover deny-only/multi-entry ACLs, process-wide FD exhaustion/release, empty content and the exact 1 MiB bound. All 51 cases pass normally and under UBSan; Clang static analysis reports no diagnostics. No native source change was required by this review. This was a parent-agent review, not an independent assessment or production acceptance.

This is not the entire maintenance acceptance matrix. Still required before production: classification and reservations, exact approval plans, versioned durable intents/events, retention/quarantine clock validation, forged-intent recovery tests, cooperative writer-lock integration, syscall-failure/power-loss matrix, broader native memory review/sanitizers, packaging qualification and a separately approved MCP/deployment gate. No binary is shipped by this change.

The approved **strictly more than 90 elapsed days after verified abandoned quarantine** is recorded in the design, not implemented in these primitives. Committed-record retention, clock-ahead criteria, scenario judgments and notification conditions are unchanged. Dot stays paused.

Pinned directories prevent pathname substitution from redirecting operations to an external victim. They do not guarantee that a directory stays at its original path during a concurrent rename. `unlinkat` is not an inode-conditional atomic unlink; private slots are not isolation from a malicious same-UID process or administrator. No secure erasure, power-loss proof or production acceptance is claimed.

## Read Protocol 2 (Slice B)

`info()` retains `protocol: 1` for the original primitive API and advertises the separate `read_protocol: 2`. `openSyntheticNativeBarReader(root, ttlMs)` requires that read protocol; an older/missing backend or non-macOS host refuses without fallback. It opens the same **synthetic fixture allowlist only** and creates nothing. The native read lease cannot enter legacy `inspect`, `stage` or `purge`; its snapshot handles are also distinct opaque native types. These are Node-API exports, not MCP tool registrations.

The reader exposes `inventory()`, `close()` and no mutation method. A snapshot exposes a detached `report`, collection-start/end UTC strings, `readEvidence(index)`, `verify()` and `close()`. Snapshot mutation in JS cannot alter native selection/proofs. Evidence reads take a validated numeric index into that exact snapshot, not caller paths/inodes or serialized proofs. Foreign/forged/closed snapshot handles refuse. Close/expiry/GC releases descriptors and memory only. One live snapshot per lease bounds retained native inventories; closing it does not reset the lease's cumulative read-byte count or either original deadline.

The native collector walks pinned no-follow descriptors, enumerates all names, and compares two bounded metadata/ACL inventories including unknown entries. Proofs expose lossless decimal device/inode/owner/mode/link/size/flags and birthtime/mtime/ctime; root/parents remain pinned/rechecked. It verifies local APFS, enforced ownership, extended ACL support, exclusive-rename capability, valid case-sensitivity and case-preservation flags. Owner-read-only fixture directories can be inspected without a write/probe; this is not a writable-root qualification. Unsupported/unverifiable properties refuse; no permission repair or platform fallback is attempted.

UTF-8 names are retained as actually enumerated. Normalized/case-folded collisions refuse; exact observed component names are rechecked when reopening evidence. Evidence identifiers use the same grammar as the TypeScript readers: lower-case UUIDs with RFC version 1-8 and variant 8-b, or nil/max. Reserved-root case variants, any case- or Unicode-folded variant of an evidence name (on a case-insensitive volume it can be the object a reader opens by its canonical name), malformed private operation names and wrong object kinds at known evidence/directory names set `namespace_qualified: false`; a lower-case non-RFC identifier is an unknown side file. Unknown ordinary side files remain visible and preserved, without being decoded as corrupt receipts. Unsafe permissions, links, nonregular objects, oversize or unknown files cannot supply readable evidence; ACL grants on the root or a directory, and ACL read errors, refuse the collection; a grant on a single file preserves that file as `preserved_unsafe_acl` (`acl: unsafe`), never readable evidence. Preserved links, nonregular objects and unsafe-mode files are not opened: their proofs come from `fstatat` on the pinned parent rather than an object descriptor. No symlink target or FIFO content is read. Private-namespace qualification is structural, not a receipt/provenance/JSON/calendar/eligibility judgment.

Evidence content is read only on demand, through revalidated root/parent/file descriptors with before/after metadata and ACL checks, bounded bytes and SHA-256. File birthtime is included in identity comparison. Source replacement, changed content, reentrant/async hooks or expiry refuse; a read error never returns partial bytes as success. The final `verify()` compares the immutable inventory to a newly enumerated view, including unknown names and reference metadata. After reading a set of files, a future collector must perform that final verification before deriving its trusted higher-level view. Individual content reads do not claim to refresh every unrelated reference. Collection UTC strings are observation brackets, not authenticated historical time.

Limits remain 30,000 entries, 1 GiB summed native entry sizes, 1 MiB per readable artifact, 16 MiB recognized metadata, 256 MiB content reads per lease and 8 MiB response bound, plus depth 16, relative paths 512 UTF-8 bytes, eight root leases and 512 shared descriptors. Read traversal keeps only a bounded directory stack and one file open, not one FD per inventory item. Response accounting charges 512 bytes per entry for every fixed key and maximal decimal/label value, plus each path in its worst JSON form, and Buffer JSON bytes for content; it may refuse before actual JSON would reach 8 MiB, never truncate or raise a ceiling. A store-sized inventory of about 4,800 entries fits; roughly 14,000 entries with typical paths remain reportable. Each evidence read re-enumerates every ancestor directory to recheck exact names, so reading all files of a 2,000-file directory takes about 20 s; daily partitions keep directories small. Synthetic `limits` may only lower fixed ceilings, never add options or increase them. Inventory sizes/estimates are not physical disk reservations.

Every report/evidence/verification says `execution_available: false`. `elapsed_clock_qualified: false` is deliberate: no OS boot-relative source or cross-boot age proof is established here, and no age/holding evidence is persisted. No fresh profile initialization/migration, policy compatibility bridge, liveness authority, writer exclusion, authenticated consent, transaction parsing/status composition, exact publication plan, journal, cleanup or native mutation coordinator is connected. Slices C-F and all production/MCP/real-data gates remain separate.

Slice B tests use invented files in fresh private synthetic roots and sibling victim fixtures only. They cover birthtime/raw hashes, ACL allow/deny/inheritance, Unicode/case changes, malformed private namespaces, FIFO/link/oversize preservation, substitutions, metadata drift, budgets, expiry, opaque handles, FD pressure and GC/close recovery. Unsupported-platform and missing-backend unit tests exercise refusal without loading a backend. Actual unsupported volume/remount/capability-error injection, power interruption, ASan and independent review remain unperformed; local APFS/UBSan tests do not establish production acceptance or authenticated time.

Pre-commit slice B review on 2026-10-23 JST corrected two low-priority lifecycle gaps. Closing an inventory now frees its vector allocation immediately, even if JS retains the closed handle; a source-boundary regression guards against replacing this with `clear()`, which retains capacity. Evidence reads also recheck the original lease after assembling the response. A native regression uses a synchronous JS property setter during response construction to cross that deadline, verifies refusal and descriptor release, and was reproduced against the uncorrected build. Both regressions failed before correction. This is a parent-agent review, not an independent assessment or production acceptance.

## Coordination Protocol 3 (Slice C)

The separately approved synthetic-only coordination extension is described in the [slice C contract](../../docs/NATIVE_BAR_EXECUTION_RECOVERY_DESIGN.md#slice-c-synthetic-coordination-boundary). `openSyntheticNativeBarCoordination` requires `coordination_protocol:3`, the same marked temporary fixture allowlist and qualified pinned descriptors; it has no pathname fallback. Its native handles are not read/legacy mutation handles. It only reads/publishes/releases root writer coordination files and retires an exact lock/takeover file only after the adapter rereads it and an injected liveness judge (the registry passes the writer algorithm verdict from `nativeBarAccess.ts`) proves its owner dead in the same call; without a judge it refuses. Opening needs two identical inventory passes, so it refuses while peers change the root; callers retry briefly. It cannot name data artifacts or a transaction journal.

The existing bakery/liveness/takeover algorithm is shared through a store adapter, not reimplemented as a competing lock. Exact native-owned deltas permit only this lease's coordination changes; other files, owners and ACL changes stale the plan. Retirement preserves evidence and requires a new preview. Original deadlines, eight root leases and 512 descriptors stay fixed; expired leases retain pins solely for explicit exact-owned cleanup, and GC never removes files. Generated interrupted coordination temporaries are preserved, not automatically repaired.

`createSyntheticNativeBarExecutionRegistry` is disconnected from MCP/history/classification and mints fixture-only consent for coordination probes, not host approval or a data execution grant. Every outcome remains `execution_available:false`. Publication is capped at 64 per lease, 128 bytes per new owner body; observations are capped at 256 bytes, retirements at 16, and actual hash/content rereads at 256 MiB. The root must have 128 logical-entry/16 KiB inventory and metadata headroom plus a 4 MiB available-space estimate. These bounds cover coordination only, not a durable data transaction or reserved disk space. Full profile/eligibility/canonical decoding/elapsed-clock/host-approval/publication/recovery integration remains future work. No binary packaging, MCP registration or production enablement changes.

## Quarantine Protocol 4 (Slice D)

See the [synthetic D contract](../../docs/NATIVE_BAR_EXECUTION_RECOVERY_DESIGN.md#slice-d-synthetic-quarantine-boundary). `createSyntheticNativeBarQuarantineRegistry` exercises immutable metadata publication and move-only quarantine in a fresh, pre-existing marked temporary fixture with the exact protocol-4 synthetic policy. The opaque native plan shares its C lease/lock, predeclares every destination/temporary and enforces pending/verified phase order. A strict v4 intent envelope retains that original plan and embeds the unchanged A transaction model. The scope is at most 16 invented capture targets and 128 initial entries, with 64 KiB records, derived peak budgets, actual preallocation and the existing global limits. No producer eligibility, real v1/profile migration, purge or host approval is inferred.

The D implementation never unlinks data, interrupted publication temporaries or its reserve file. It retains partial layouts, journals and conflicts without repair. Files request `F_FULLFSYNC`, directories `fsync`, followed by native readback, and one final root `F_FULLFSYNC` follows the completion; a reserve left by an interrupted run blocks new plans, and restart inspection refuses unplanned objects in the transaction namespaces; tests do not qualify power-loss durability. A local optional protocol-4 backend is required, with no compilation/download/pathname fallback. The ordinary MCP startup and binary packaging are unchanged.

`inspectSyntheticNativeBarQuarantine` reopens a read-only native snapshot, validates canonical UTF-8 bytes and the original plan/records/actual locations, and never locks or resumes. Original response acknowledgement remains unproven after restart. Existing transaction namespaces refuse new execution; a fresh-approved recovery executor is deliberately not yet connected. Elapsed-clock qualification and production execution remain unavailable. Run the normal synthetic test command above, optionally with `--ubsan`, to include D and its operation-boundary/process-death fixtures.

## Recovery Read Protocol 5 (R-B)

The commit review adds per-ancestor response accounting. The local v5 controller also seals the prepared directory identities/full access evidence and separates the original reference audit hash from the current complete-inventory generation. Native reads remain read-only; neither these facts nor the new strict v5 fields authenticate host approval or a historical write acknowledgement.

`info().recovery_read_protocol:5` and `openSyntheticNativeBarRecoveryReader` add a **separate read-only mode**, not a protocol-5 executor. The opener requires the same private marked temporary fixture allowlist and exact canonical `native-bar-synthetic-quarantine-recovery-profile-v5` policy. It creates nothing. The read-only C session cannot enter legacy target or coordination primitives; read protocol 2 and protocol-4 profile/refusal behavior remain unchanged. There is no binary packaging, normal-startup compilation, MCP registration or production enablement change.

V5 inventory/evidence additionally report complete descriptor ACL digests and lossless `st_blocks * 512` allocation, plus immutable ancestor facts. The original snapshot verifies root/parent/file identity, flags and complete ACLs before/after content reads and on final inventory verification. Attempt-specific timestamps and declared root temporary/reserve patterns are recognized without relaxing the old grammar. Ordinary safe root files may be hashed, never interpreted as receipts or repaired. Preserved links/unsafe/nonregular/unreadable entries cannot qualify a high-level view.

The hard enumeration limit is 512 (128 for fresh controller admission), including unknown entries. Artifact 1 MiB, metadata 16 MiB, inventory 1 GiB, actual content reads 256 MiB, response 8 MiB, eight root leases and 512 shared FDs stay fixed. Caller limits only lower them. Opening's policy read is charged; closing/reopening a snapshot does not reset reads or deadlines. Final `verify()` in this mode returns fresh native accounting alongside successful verification; the legacy wrapper still returns its original Boolean-shaped result. Available-space estimates and physical block counts are not a reservation or proof of future space, clone/compression fidelity, elapsed age or production suitability.

The [R-B controller contract](../../docs/NATIVE_BAR_QUARANTINE_RECOVERY_DESIGN.md#r-b-implemented-boundary) binds this native view to independently supplied invented-input commitments and an in-memory owner ledger. No view mints execution/host consent or recovers a lost controller from JSON. R-C/D and slice E remain separate gates. The native test command includes R-B; its test-only reserve-setup executable is compiled into a temporary fixture parent, never into the addon, and only creates a new empty preallocated reserve under a marked fixture. Fixture setup/seeded journals/moves are test effects, not runtime behavior or writer durability qualification.
